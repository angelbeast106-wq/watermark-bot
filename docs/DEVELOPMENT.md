# Development guide

## Локальный запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

После этого нужно:

1. Вставить реальный `BOT_TOKEN` в `.env`.
2. Положить PNG-логотип в `assets/watermark.png`.
3. Запустить:

```bash
python bot.py
```

## Конфигурация

Все runtime-настройки читаются из `.env` при импорте `bot.py`.

- `BOT_TOKEN` - токен Telegram-бота.
- `WATERMARK_PATH` - путь до PNG-логотипа.
- `WATERMARK_ANCHOR` - базовая позиция watermark, для текущего проекта используется `top_right`.
- `WATERMARK_WIDTH_PERCENT` - ширина watermark в процентах от ширины изображения.
- `WATERMARK_MARGIN_PERCENT` - общий отступ в процентах от меньшей стороны изображения; в текущем проекте `6`.
- `WATERMARK_TOP_MARGIN_PERCENT` - отдельный верхний отступ; в текущем проекте `0`.
- `WATERMARK_OPACITY` - прозрачность от `0` до `1`; в текущем проекте `1`.
- `SHIFT_STEP_PX` - шаг горизонтального сдвига кнопками.

## Проверки перед изменениями

Минимальная быстрая проверка синтаксиса:

```bash
python3 -m py_compile bot.py watermark_processor.py
```

Когда появятся тесты:

```bash
pytest
```

## Рекомендуемый порядок разработки

1. Сначала менять и тестировать чистую логику в `watermark_processor.py`.
2. Затем подключать новую возможность в Telegram-сценарии в `bot.py`.
3. Для новых callback-кнопок держать callback data короткими и явными.
4. Для новых настроек добавлять переменную в `.env.example` и описание в README.
5. Для рискованных изменений добавлять unit-тесты на рендер или расчет координат.

## Соглашения по коду

- Telegram-специфичный код остается в `bot.py`.
- Pillow-логика остается в `watermark_processor.py`.
- Новые dataclass-модели стоит держать маленькими и явно типизированными.
- Пользовательские сообщения сейчас на русском, технические ошибки в коде могут быть на английском.
- Не хранить реальные токены и пользовательские изображения в репозитории.

## Что стоит сделать перед активной разработкой

- Добавить `pytest` и первые тесты на `_calculate_position()`.
- Решить, нужен ли Redis/TTL для сессий или пока достаточно памяти процесса.
- Добавить обработку документов без `mime_type`.
- Добавить ограничения на размер входного файла.
- Убрать пустые log-файлы из репозитория, если они не нужны как артефакты.
